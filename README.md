# maor-equity

A two-node heterogeneous pipeline for automated equity research: five agents over
SEC filings and market data, built to run under a hard 4 GB VRAM budget.

**Status: under remediation.** A [publication-readiness audit](docs/AUDIT_RESPONSE.md)
found that the previously published H1/H2/H3 results were generated by scripts
rather than measured, and that the one real latency measurement contradicted the
published claim. The evidence base is being rebuilt. See
[`docs/RESULTS_STATUS.md`](docs/RESULTS_STATUS.md) for what has actually been
measured so far, and [`docs/EVIDENCE_POLICY.md`](docs/EVIDENCE_POLICY.md) for the
rules that now prevent a recurrence.

Do not cite any number from this repository that does not appear in
`docs/RESULTS_STATUS.md`.

---

## Quick start

```bash
pip install -r requirements.txt
python -m maor.cli doctor
```

`doctor` reports your hardware, dependencies, dataset availability and VRAM
budget, and tells you which experiments can run here.

Run the one experiment that needs no GPU:

```bash
python -m maor.cli h3-sentiment
```

Run the tests:

```bash
python -m pytest tests/ -q
```

## What the system does

| Stage | Where | What |
|---|---|---|
| Chunking | CPU | 512-token windows, 64-token stride (87.5% overlap) |
| ChunkFilter | CPU | TF-IDF density scoring, greedy near-duplicate removal, hard cap |
| Dimension routing | CPU | Lexical regex routing to market / regulatory / temporal |
| Sentiment | GPU | FinBERT over each dimension, producing a 3×3 matrix with explicit missingness |
| Summarisation | GPU | Map-reduce over filtered chunks via a shared Phi-3-mini |
| Guardrail | GPU | Opposing Bull/Bear stances resolved by a deterministic arbiter |

Phase A (sentiment) and Phase B (summarisation, guardrail) are **phase
serialised**: each releases its VRAM before the next loads, so peak residency is
`max(A, B)` rather than `A + B`. That is what allows a 3.8B model and two BERT
classifiers to run on a 4 GB card.

## Configuration

Everything that can change a measured number lives in `configs/`. The SHA of the
resolved configuration is recorded in every result.

```bash
# Use a different config file
python -m maor.cli h3-sentiment --config configs/gpu_t1000.yaml

# Override individual values
python -m maor.cli h3-sentiment --set execution.device=cpu --set execution.seed=7
```

Unknown keys are an error rather than a silent no-op, so a typo fails the run
instead of quietly measuring the default.

### VRAM is a hard constraint

`vram.total_mb: null` probes the device rather than assuming 4 GB, so the same
code runs unchanged on a larger card. `usable_fraction` reserves headroom for the
CUDA context, allocator fragmentation and KV cache growth, none of which appear
in `torch.cuda.memory_allocated`.

The budget refuses an allocation **before** weights load, and refuses to load the
same model twice:

```python
budget.reserve("phi3", 2800.0)   # raises VRAMBudgetExceeded if it will not fit
budget.reserve("phi3", 2800.0)   # raises ModelAlreadyResident
```

That second guard matters: the shared summariser exists specifically so a ~2.7 GB
residency is paid once, and loading it twice is the easiest way to exhaust a 4 GB
card.

## Running experiments

| Command | Needs GPU | What it produces |
|---|---|---|
| `doctor` | no | Environment, dependency and data check |
| `gpu-audit` | no | Device memory, model residency, workload feasibility |
| `h3-sentiment` | no | H3: multi-dimensional vs scalar sentiment |
| `chunk-filter` | no | ChunkFilter cost and coverage curve |
| `smoke` | either | End-to-end wiring check |
| `fetch-models` | no | Pre-downloads all checkpoints |
| `vram-verify` | yes | Measured VRAM trace against the budget |
| `h2-summarisation` | yes | H2: map-reduce vs single-pass on ECTSum |
| `h1-latency` | yes | H1: 2×2 factorial latency study |
| `run-all` | either | The full sequence, with cleanup between experiments |
| `verify-cluster` | no | Ray cluster health |
| `report` | no | Regenerates tables and `RESULTS_STATUS.md` |

Global flags (`--config`, `--set`, `-v`) work before or after the subcommand.

GPU commands detect a missing CUDA device and report `BLOCKED` — implemented but
unrunnable here — rather than failing obscurely or producing CPU numbers that
would not transfer.

Full instructions for the GPU node: [`docs/GPU_RUNBOOK.md`](docs/GPU_RUNBOOK.md).

### GPU memory is managed, not hoped for

Models load only when needed and are released in `finally`, so a failed or
timed-out experiment cannot leave weights resident for the next one. Release is
verified by measurement — moving to CPU, dropping references, emptying the cache,
then checking what actually came back — because clearing an attribute is not a
release when a pipeline, a returned tensor or a traceback still holds the model.

A registry refuses to load the same checkpoint twice on one device, the budget
holds a reservation for as long as the model is resident, and every experiment
records peak and residual memory so a leak shows up as a number rather than as a
mysterious out-of-memory error three experiments later.

See [`docs/VRAM_LIFECYCLE.md`](docs/VRAM_LIFECYCLE.md) for what is guaranteed and,
just as importantly, what is not.

## Results

Every result file in `results/` embeds its own provenance: git commit and whether
the tree was dirty, timestamp, host, exact command, library versions, config SHA,
seed, and the hardware it was measured on. `read_result()` refuses to load a file
without it, so hand-written numbers cannot be cited by accident.

Results are classified `MEASURED` or `DERIVED`. There is deliberately no class
for estimated or projected values — if a quantity has not been measured, it is
reported as not-yet-measured, with the command that would produce it.

### Measured so far

**H3 — multi-dimensional sentiment does not change recommendations.**
On all 4,846 Financial PhraseBank sentences with real FinBERT checkpoints, the
multi-dimensional system produced **identical** directional recommendations to
the scalar baseline: 0.00% divergence, 0.00 pp accuracy difference. Both H3a and
H3b **FAIL**.

The reason is structural rather than incidental. The temporal dimension is scored
by the market checkpoint; when it receives the same text as market — always, at
sentence granularity — deterministic inference forces an identical label, making
any rule that requires the two to disagree unsatisfiable. Separately, the lexical
router matched only 8 of 4,846 sentences (0.2%) as regulatory, so the regulatory
veto was effectively never exercised.

This result carries a critical validity threat recorded in the result file:
`ProsusAI/finbert` is fine-tuned on Financial PhraseBank, so absolute accuracy
figures measure memorisation rather than generalisation. The *contrast* between
the two arms remains interpretable because both use the same market model.

See [`docs/RESULTS_STATUS.md`](docs/RESULTS_STATUS.md) for the full table.

## Development

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -q
```

`tests/test_audit_regressions.py` contains one test per audit finding. They are
written so that reintroducing a defect fails the suite — for example, a parse
failure in the guardrail must produce `ASSESSMENT_FAILED` rather than a
confident-looking `UNRESOLVED`, and a hypothesis test whose threshold lies
outside its metric's achievable range is flagged as unfalsifiable.

## Hardware

- **Node A** — CPU workstation: ingestion, chunking, filtering, routing, orchestration
- **Node B** — NVIDIA T1000, 4,096 MB VRAM: all model inference

Single-node execution is the default and is valid for every claim except the
cross-node communication measurement. Distributed mode (Ray) is optional.

## Datasets

| Dataset | Use | Source |
|---|---|---|
| Financial PhraseBank (Malo et al., 2014) | H3 | Parquet mirror; the upstream loader script no longer runs under `datasets>=4` |
| ECTSum (Mukherjee et al., EMNLP 2022) | H2 | `data/ectsum/ectsum_test.jsonl`, 495 test records |

The loaders verify what they loaded rather than trusting a repository name: the
PhraseBank split is identified by row count and label distribution. Worth noting,
since the original documentation conflated them — the mirror is the
**50%-agreement** split (4,846 sentences), not the 75%-agreement split (3,453).
